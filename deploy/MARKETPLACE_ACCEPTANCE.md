## 已验证的软件行为

- [x] 两处财务漏洞专项回归：拒付后恢复来源不能再重复退款；充值赠额与订单现金分开，按原订单比例退款/拒付及处理舍入尾差。
- [x] 真实 PostgreSQL 来源账、冻结、原子捕获、C=S+F、幂等、消费退款、收益成熟、手动提现状态机、拒付与对账。
- [x] 同一用户消费者/供应者模式、owner 权限、账号生命周期、已发布并发上限、禁止自消费；没有租户或账号租约。
- [x] 真实应用进程的 Chat/Responses 普通、流式、function tools、缓存 usage、API Key 鉴权、缓存预热后的共享调度；模拟上游，六笔结算及槽位释放。
- [x] 多 handler、10 买方/10 账号、并发 1/3；未知结果不重试/不虚构收益，DB/Redis 故障、关闭开关后的收尾。
- [x] 超过两小时未更新的未完成 receipt 定时转人工审核；不自动解冻；无任何 attempt 的审计释放与已知 usage 继续捕获。
- [x] 精确金额的管理员拒付登记、原订单所有者解析、强二次验证、同事件重放/冲突；没有支付方自动 webhook。
- [x] 误解冻执行异常的不可变登记/查询、强二次验证、同键冲突/并发与审计正文保护；登记不改变任何资金记录。
- [x] 前端 397 文件/3015 测试，补充政策未保存/提交竞态与异常登记重试用例；typecheck、i18n、lint 和构建。
- [x] Compose 的 MARKETPLACE_* 配置注入和默认关闭检查；部署脚本、开发环境、依赖、生产镜像模式、安全、运行资源及 Caddy 检查。
- [x] 360/768/1440 与明暗主题代表页面人工检查；审核键盘操作/焦点返回、政策取消离开保留草稿、移动异常弹窗滚动/按钮可达。完整视觉矩阵仍见下方门槛。

本地仓储/handler 用例、真实应用进程用例和门户观察具有不同边界：前者使用部分 fixture/桥接，真实进程使用真实网关组件但以 SQL fixture 建立账号和资金来源，门户审核写入/银行转账并未全部由浏览器串起。不得将其合称为真实商业资金链验收。
