## 错误原因及证据

本轮 32 个失败实例的 worker 日志均显示真实上游 HTTP 429、`classified=upstream`，并出现 `FreeUsageLimitError` / `Free usage limit reached`。每条失败的 request ID、account ID、proxy ID 和 model 均与目标一致；归属冲突及字段不符均为 0。32 条错误正文均为完整 208 字节 JSON，未截断，留在私有证据中。

这确认了上游以免费层限额错误拒绝当前调用。实例使用绑定代理访问匿名免费入口，没有独立上游账号余额查询结果，因此不能把该错误进一步写成已核实某个注册账号的 remaining=0，也不能断言上游限额只按 IP、模型或某一固定周期计算。

本轮为单条 user 消息的最小文本对话，没有工具目录；不能据此声称 OpenClaw、DeepSeek Harness 的完整工具往返也已通过。后台外层 HTTP 200 只表示诊断 SSE 已建立，流内 error 的实例仍计失败。

用户余额：测试前 999.99048689 USD，测试后 999.99044399 USD。已结算余额扣费合计 **0.0000429 USD**，与余额差额一致；Mimo 0，DeepSeek 0.00004290 USD（输入 0.00003210 + 输出 0.00001080）。两次上游均标注 free，但本站 DeepSeek 分组仍按其价格配置收取消费费用，不能用上游 cost=0 推断本站用户免费。

## 状态与测试范围

提示词：`What is 2 + 3? Reply with only the number 5.`。每个模型的每个实例均单独新会话，固定账号、绑定代理、一次 worker 派发；共 42 次固定实例主调用，无人工重试、无跨账号故障转移。消费入口的两次补充请求另计。消费网关自身可按实现故障转移或自动复验，不能将 HTTP 请求数直接等同于所有上游派发数。

测试前 42 个实例均无尚未到期的冷却。后台成功测试会按现有逻辑恢复运行时状态；命中免费层限额错误会自动写入冷却。当前生产源码的冷却 fallback / 上限均为 12 小时，有合法更短 Retry-After 时保留更短时间，最短 1 分钟。冷却到期后按调度器重建恢复候选资格，届时上游是否已恢复仍须真实调用确认。

本轮未手动暂停实例、未清理冷却或重置 usage。42 个实例的完整 credentials、代理绑定、分组绑定、并发和优先级等配置指纹一致，schedulable 开关前后一致；两个分组配置一致。后台自动写入或清除的运行时限制保留。独立复核另检查代理定义和 Key 配置。

两个分组的派生统计 `active_account_count` 由 21 变为 5，`rate_limited_account_count` 变为 16；这些是测试产生运行时冷却后的统计变化，不是分组配置变更。原始 report 对完整 group 对象的比较为 false，独立复核只排除这两个已解释的计数字段后，确认其他分组字段一致。
